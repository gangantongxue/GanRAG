# GanRAG 产品形态文档

## 概述

GanRAG 是一个 GitHub 风格的知识库产品：用户创建知识库、以目录树组织 md/txt 文章（支持 pdf / docx / html 文档上传转 md）并配图，内置 AI 聊天基于知识库内容检索回答问题；知识库具有公开/私有属性与社交关系（成员、star、关注），这些关系状态同时也是 AI 检索排序的权重信号。P3 由独立社交图服务把直接关系与结构派生信号分数化后接入召回排序，设计见 [social-recall.md](social-recall.md)。

本文档定义产品形态、功能范围、权限模型与分期路线；服务实现见各服务 `docs/architecture.md`，表结构见 [data-model.md](data-model.md)。

## 界面布局

登录后的主界面为三栏结构：

```
┌───────────────┬──────────────────────────┬───────────────────────┐
│  知识库列表     │                          │   聊天会话历史列表      │
│  （左侧栏）     │       AI 聊天框           │   （右侧栏）           │
│               │       （中间主区域）        │                       │
│  [搜索框]      │                          │   · 会话 1（绑定库 A） │
│  · 我的        │   消息流 + 输入框          │   · 会话 2（全局）     │
│  · 我是成员的   │   （流式渲染 Markdown）     │   · 会话 3（绑定库 B） │
│               │                          │   · ...（按时间倒序）  │
│  · 新建知识库   │   [检索范围选择器]          │                       │
└───────────────┴──────────────────────────┴───────────────────────┘
```

- **左栏**：只展示**我的**和**我是成员的**知识库（星标库、他人的库**不在左栏展示**）；顶部搜索框用于搜索他人的公开知识库，搜索结果点击进入
- **中栏**：AI 聊天，顶部检索范围选择器（某个知识库或全局），回答流式渲染 Markdown
- **右栏**：聊天会话历史，按最近活跃倒序，显示所属检索范围标签，点击恢复会话

**发现入口（不在左栏）**：

- 他人的知识库 → 通过搜索进入
- 我 star 的知识库列表 → 个人页面查看
- 我的关注列表 / 我的粉丝列表 → 个人页面查看

## 功能清单

### 账号（User 服务）

- 注册、登录（双 token）、刷新、修改密码、按 ID 查询用户
- 关注 / 取消关注其他用户；关注列表查询
- 设计详见 [service/user/docs/architecture.md](../service/user/docs/architecture.md)

### 知识库（Repository 服务）

| 功能 | 说明 |
|------|------|
| 创建知识库 | 名称在本人名下唯一，可填描述 |
| 公开 / 私有 | `visibility`：private 仅 owner 与成员可见；public 所有人可见、只读 |
| 成员管理 | owner 可添加 / 移除成员、设置角色（reader / editor）；公开库也可添加成员以提升权限 |
| star / 取消 star | 任何能看见该库的用户可 star；**不能 star 自己拥有的库**；star 计数冗余存储 |
| 目录树 | 任意层级目录，同一父目录下名称唯一；文章移动 = 改父目录，不影响已有引用 |
| 文章 | 类型 md / txt；正文存 Garage（`articles.content_key`），按目录增删改、移动、重命名 |
| 文档上传 | 类型 pdf / docx / html，上传即用 markitdown 转为 md 存储，**原文留档**（附件可下载）；**内容只读**，更新 = 重新上传 |
| 图片附件 | 编辑时上传到 Garage 对象存储（统一单桶、key `o/<obj_xid>`），md 中只写**相对路径**（如 `assets/img.png`），前端渲染时以当前文章为基准解析并拼 Gateway 资源地址 |
| 文章互链 | md 中指向其他文章的相对路径链接，保存时解析为**文章 ID 稳定 URL**，移动/重命名不失效；失效链接渲染时标记 |

> **上传入口须明示**：支持 md / txt / pdf / docx / html；其中 pdf / docx / html 会转为 md 存储，**内嵌图片不提取、不做 OCR**——图片中的文字不进检索，此类文档**向量化与检索效果不好**；扫描件（无文字层）转换为空将拒绝上传。

### 社交与发现

| 功能 | 说明 |
|------|------|
| 知识库搜索 | 左栏搜索框，按名称/描述搜索**他人的公开知识库**，结果点击进入；他人的库不进左栏 |
| 关注 / 取消关注 | 任何登录用户可关注他人（不能关注自己） |
| 我 star 的列表 | 个人页面查看（**不在左栏展示**），点击进入对应知识库 |
| 我的关注 / 粉丝列表 | 个人页面查看，点击进入用户主页（主页展示其公开知识库） |

### AI 聊天（AI 服务 + Gateway）

| 功能 | 说明 |
|------|------|
| 检索范围 | 会话创建时绑定：**某个知识库** 或 **全局**；范围随会话固化，重新打开历史会话即回到当时范围 |
| 可见性过滤 | 全局检索的候选集 = 我的 + 我是成员的 + 公开库（P1 必须保证私有库不泄露） |
| 权重排序 | 权限过滤后合并向量召回与关键词召回，使用社交分数、star 热度、时效排序，并由 Decima-small 对前排候选做相关性审查（P3） |
| 会话历史 | 会话与消息持久化，右侧栏按最近活跃倒序；模型上下文（压缩摘要）存会话侧、不进消息流，页面只显示真实对话 |
| 流式回答 | SSE 流式输出，前端 Markdown 渲染 |
| 智能体路由 | 每条消息经本地 Decima-small 在全部 Agent 中选择概率最高者执行（P1.5） |
| 智能体切换 | 当前 Agent 概率低于可调阈值后，才在全部 Agent 中重新选择；最高者仍是当前 Agent 时不切换（P1.5） |
| 上下文交接 | 上下文达到约 65% 容量时压缩；只保留最新隐藏 Agent 提示词并置于压缩摘要前，用户消息流不展示（P1.5） |

### 社交关系状态（核心概念）

知识库相对当前用户的**关系状态**必须显式存储，作为检索权重信号：

| 信号 | 来源 | 含义 |
|------|------|------|
| `OWN` | `knowledge_bases.owner_xid = me` | 自己创建的库 |
| `MEMBER` | `kb_user_relations.role >= 1` 命中 | 自己是成员的库 |
| `STARRED` | `kb_user_relations.starred = 1` 命中 | 自己 star 的库（即关注该库） |
| `FOLLOWED_AUTHOR` | `user_follows` 命中库的 owner | 自己关注的作者创建的库 |
| `OTHER` | 以上皆无 | 其他人的库（仅 public 可见） |

**发现入口约定**：左栏只放「我的 + 成员的」（高频工作集）；star 与关注列表放个人页面；他人的库靠搜索发现——避免左栏被低频内容淹没。关系状态仍全部显式存储，服务于检索权重。

**star 即关注知识库**：用户 star 一个知识库就表示关注它，不另外维护「关注知识库」表；关注用户仍走 `user_follows`，与是否 star 其知识库无关。

一个库可同时命中多个信号（如既是成员的又 star 的）。

## 权限模型

角色由「库归属 + 成员表 + 可见性」推导，**不为公开库的陌生人建成员行**（陌生人对公开库的只读权限由 `visibility` 推导）：

| 动作 | owner | editor 成员 | reader 成员 | 公开库陌生人 | 私有库陌生人 |
|------|:-----:|:-----------:|:-----------:|:------------:|:------------:|
| 浏览 / 阅读文章 | ✅ | ✅ | ✅ | ✅ | ❌（返回 NotFound，不暴露存在） |
| 编辑 / 移动 / 删除文章与目录 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 上传图片附件 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 添加 / 移除成员、改角色 | ✅ | ❌ | ❌ | ❌ | ❌ |
| star / 取消 star | ❌（自己的库） | ✅ | ✅ | ✅ | — |
| 删除知识库 | ✅ | ❌ | ❌ | ❌ | ❌ |
| AI 检索（聊天范围内可见） | ✅ | ✅ | ✅ | ✅ | ❌ |

**社交关系**：任何登录用户可关注他人（不能关注自己）；关注与 star 关系公开可见（GitHub 式），不做私密设置。

## 检索权重与社交召回（P3）

关系状态 → 权重映射由 AI 服务持有（配置项，非数据库存储），数据库只负责存储关系状态。P3 升级为「社交分数 + star 热度 + 时效」三路信号，权重不写死在产品文档，具体数值由公开数据集实验标定、真实日志/A/B 测试微调（见 [social-recall.md](social-recall.md)）。

**关系优先级（只给序关系，不给等距数值）**：

| 优先级 | 信号 | 来源 |
|---|---|---|
| 最高 | 自己的文章 / 自己的知识库 | `articles.created_by_xid` / `knowledge_bases.owner_xid` |
| 很高 | 互相关注作者 | `user_follows` 双向 |
| 较高 | 单向关注作者/库主 | `user_follows` |
| 中高 | 协作者（KB 成员） | `kb_user_relations.role >= 1` |
| 中 | star 该知识库 | `kb_user_relations.starred`（star 即关注该库） |
| 中低 | 二跳关注 | 社交图服务 BFS |
| 低 | 同社区、共同关注重合 | 社交图服务派生 |
| 低（更弱） | star 过该作者的其他知识库 | 作者聚合弱信号 |
| 兜底 | 公开文章 | `visibility = 1` |

- 多信号同时命中时**直接关系取最高档**，结构派生信号（PageRank/社区/Jaccard）作为加成项，不做无上限叠加；
- 时效是**乘性**衰减；star 与社交是**加性**融合；Decima-small 只做 Top-K 符合度审查，不承担社交打分；
- 权限过滤永远先于召回与排序，社交分数不能改变可见性；
- 权重值与合并策略均为 AI 服务配置，P3 阶段用公开数据集标定，并保留各信号支持解释与消融。

> 工程实现：独立 `social-graph` 服务（P3）负责关系图与社交分数，AI 服务负责最终融合；设计见 [service/social-graph/docs/architecture.md](../service/social-graph/docs/architecture.md)。

## 分期路线

| 阶段 | 范围 | 关键交付 |
|------|------|----------|
| **P1 内容 + 聊天闭环** | 账号、知识库 CRUD、目录树、文章（md/txt）、图片与互链、三栏界面、会话绑定范围的 AI 聊天 | 私有库**可见性过滤**必须正确（不加权也绝不泄露）；关系状态字段随表落地 |
| **P1.5 文档上传 + 多智能体** | pdf / docx / html 上传转 md（markitdown）；Decima-small Agent 路由、阈值切换、隐藏提示词、上下文压缩、`search_context` 工具 | 文档入知识库 + 专项智能体能力；设计见 [service/ai/docs/architecture.md](../service/ai/docs/architecture.md) 与本文「文档上传」 |
| **P2 社交与发现** | 成员管理界面、star、关注（接口 + 界面）、知识库搜索入口、个人页面（我的 star / 关注 / 粉丝列表） | 关系状态数据完整，为排序信号提供数据 |
| **P3 社交召回与权重** | 独立社交图服务（互关/二跳/PageRank/Leiden/Jaccard）、社交分数 + star + 时效融合、公开数据集标定、Decima-small 候选审查、消融 | 权限先过滤，相关性为主，社交信号可解释、可调参、可降级 |

分期原则：**表结构在 P1 一次设计到位**（见 data-model.md），接口与界面按阶段交付，避免后期破坏性迁移。

## 术语表

| 术语 | 含义 |
|------|------|
| 知识库（KB） | 一个独立的知识集合，含目录树、文章、附件，有公开/私有属性 |
| 文章（article） | 知识库内的 md 或 txt 文档，靠 ID 被引用（不依赖路径） |
| 附件（attachment） | 文章引用的图片/文件，存 Garage 对象存储，元数据在 MySQL（含 `relative_path` 相对路径） |
| 检索范围 | 会话创建时固化的检索目标：单个知识库或全局 |
| 关系状态 | 知识库相对当前用户的 OWN / MEMBER / STARRED / FOLLOWED_AUTHOR / OTHER |
| 社交分数 | 用户 × 文章的关系远近分数：直接关系档位 + 结构派生加成（见 [social-recall.md](social-recall.md)） |
| 召回权重 | 语义、关键词、star、社交、Decima 审查各信号的融合配置，由数据集实验标定 |
| 关注知识库 | star 该知识库；不单独维护关注表，关注用户仍走 `user_follows` |
